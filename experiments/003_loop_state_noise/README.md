# Эксперимент 003: зашумление состояния между loops

## Мотивация и гипотеза

В Experiment 001 поздние обновления становятся почти коллинеарными с текущим
hidden state, а в Experiment 002 dropout улучшил PPL на обученной глубине, но
усилил деградацию при дополнительных loops. Проверяем, может ли небольшой
случайный сдвиг после каждого завершённого прохода выводить recurrent dynamics
из узкой траектории и заставлять общий блок учиться исправлять локальные
возмущения.

Наивный аддитивный шум опасен: его абсолютный масштаб зависит от растущей нормы
residual stream, а накопление радиальной компоненты может сделать 16 loops
нестабильными. Поэтому основной вариант использует norm-preserving noise:

1. Gaussian-вектор ортогонализуется относительно состояния каждого токена;
2. его RMS нормируется и умножается на `sigma * RMS(h)`;
3. зашумлённое состояние проецируется обратно на исходную RMS-сферу.

Таким образом шум исследует направление hidden state, не изменяя его RMS.
Шум действует только во время обучения, плавно разогревается первые 30 шагов и
добавляется между loops. После последнего loop он по умолчанию не добавляется:
там он уже не может породить дополнительное вычисление и превращается только в
шум перед LM head.

## Матрица эксперимента

Все варианты имеют 5.67M параметров, два общих Qwen3-слоя, 16 train loops и
одинаковый бюджет не более 10M токенов.

| Вариант | Шум | sigma | Стабилизация |
|---|---|---:|---|
| `control_r16` | нет | 0.00 | контроль |
| `relative_s003_r16` | Gaussian | 0.03 | масштаб относительно token RMS |
| `spherical_s003_r16` | Gaussian | 0.03 | tangent noise + сохранение token RMS |

Оценка выполняется детерминированно при 1, 2, 4, 8, 12, 16, 20, 24 и 32 loops.
Для каждого числа loops сохраняются loss, perplexity, относительное обновление,
норма hidden state и cosine similarity с предыдущим состоянием.

Tokenizer, подготовка FineWeb, обучение, validation и evaluation показывают
прогресс и ETA через tqdm. Training bar обновляет loss, learning rate, gradient
norm и tokens/sec. Evaluation использует взвешенный объём работы `loops × batches`,
чтобы ранние дешёвые depth не давали заведомо заниженную оценку оставшегося
времени. Машиночитаемые train/validation records сохраняются в
`outputs/experiments/003/<variant>/metrics.jsonl`.

## Результаты

Все три запуска завершили 305 optimizer steps (последний индекс — 304) и
обработали 9,994,240 токенов.
Обучение и evaluation проводились на одном и том же seed 42. Главная метрика —
PPL@16 относительно контроля; дополнительно проверяется extrapolation до 32
loops.

| Вариант | Loss@16 | PPL@16 | Δ loss к control | PPL@24 | PPL@32 |
|---|---:|---:|---:|---:|---:|
| `control_r16` | **7.25699** | **1417.98** | — | **1424.41** | **1430.40** |
| `relative_s003_r16` | 7.25818 | 1419.68 | +0.00119 | 1427.40 | 1434.71 |
| `spherical_s003_r16` | 7.25909 | 1420.97 | +0.00210 | 1426.76 | 1433.62 |

Гипотеза при `sigma=0.03` не подтвердилась. Relative noise ухудшил PPL@16 на
0.12%, norm-preserving noise — на 0.21%. Ни один вариант не сделал
дополнительные проходы после обученной глубины полезными: лучший результат всех
трёх моделей находится около 12–16 loops, после чего perplexity монотонно
растёт. На 32 loops оба зашумлённых варианта также хуже контроля.

### Динамика скрытых состояний

| Вариант | Norm@16 | Cosine@16 | Relative update@16 | Norm@32 | Cosine@32 |
|---|---:|---:|---:|---:|---:|
| `control_r16` | 124.47 | 0.999927 | 0.07098 | **256.50** | 0.999992 |
| `relative_s003_r16` | 123.57 | 0.999912 | 0.07550 | 263.35 | 0.999991 |
| `spherical_s003_r16` | **123.52** | 0.999907 | 0.07660 | 265.25 | 0.999991 |

Шум немного увеличивает относительное обновление на loop 16, но эффект мал и
не сохраняет полезную разницу к loop 32. Во всех вариантах соседние состояния
становятся почти коллинеарными, тогда как hidden-state norm растёт примерно
линейно. Сферическая проекция устраняет радиальную компоненту самого шума, но
не ограничивает рост нормы, создаваемый повторяющимся residual update.

Особенно заметна цена восстановления после perturbations на малой глубине:
PPL@1 равен 3778.97 у контроля, 6868.73 у relative noise и 6759.32 у
norm-preserving noise. Модели с шумом научились полагаться на последующие
итерации для исправления состояния, но это не превратилось в более полезное
вычисление на 16–32 loops.

### Стабильность и стоимость

Обучение осталось численно стабильным: максимальный зафиксированный gradient
norm равен 1.723 у всех трёх запусков, spikes во время 30-step noise warmup не
наблюдались. Следовательно, отрицательный результат нельзя объяснить срывом
оптимизации. Цена perturbation при этом измерима: итоговый throughput составил
5853 tok/s у контроля, 5445 tok/s у relative noise (-7.0%) и 5179 tok/s у
norm-preserving noise (-11.5%) на Tesla T4.

Итоговая интерпретация: независимый изотропный шум повышает сложность
восстановления hidden state, но не устраняет fixed-point-like alignment поздних
обновлений. Повышать `sigma` без изменения recurrent update нецелесообразно.
Следующий эксперимент должен воздействовать на источник коллапса — например,
нормировать или гейтировать величину каждого loop update — и отдельно проверять
ненулевой relative update после обученной глубины.

Результат получен на одном seed и является пилотным. Полные метрики находятся в
[`results/summary.csv`](results/summary.csv), исходные per-loop diagnostics — в
JSON-файлах той же директории.

## Запуск

Из корня репозитория:

```bash
python experiments/003_loop_state_noise/run.py --variant control_r16
python experiments/003_loop_state_noise/run.py --variant relative_s003_r16
python experiments/003_loop_state_noise/run.py --variant spherical_s003_r16
python experiments/003_loop_state_noise/summarize.py
```

Для продолжения прерванного обучения добавьте `--resume`. Для оценки готового
checkpoint используйте `--eval-only`. Colab-процесс полностью собран в
[`experiment_003_colab.ipynb`](experiment_003_colab.ipynb).

Финальная ячейка ноутбука создаёт `experiment_003_results.zip`. Архив содержит
JSON/CSV результатов, training logs, конфиги и сведения о runtime; веса по
умолчанию не включаются, чтобы архив было удобно передать для анализа.
