# Эксперимент 002: прореживание входа повторных итераций

## Гипотеза

В контрольной модели поздние итерации вносят почти коллинеарные обновления, а остаточное состояние продолжает расти. Проверяем, заставит ли случайное зануление части рекуррентного скрытого состояния перед повторными проходами восстанавливать и перераспределять информацию.

Сравниваются три модели с одинаковой архитектурой (5,67 млн параметров, 2 общих слоя, 8 итераций) и бюджетом до 10 млн обучающих токенов на запуск:

- `baseline_r8`: контроль без прореживания;
- `dropout_p010_r8`: прореживание входа `p=0.10`;
- `dropout_p020_r8`: прореживание входа `p=0.20`.

Прореживание применяется начиная со второй итерации только во время обучения. Первый проход по эмбеддингам не изменяется, а при оценке маска отключена. Прореживание не добавляет параметров.

Контроль переиспользуется из эксперимента 001 и повторно не обучается.

## Результаты

Все модели обучались с 8 итерациями и оценивались с 1, 2, 4, 8, 12 и 16 итерациями.

| Вариант | Прореживание | Потеря@8 | PPL@8 | PPL@16 |
|---|---:|---:|---:|---:|
| `baseline_r8` | 0.00 | 7.0257 | 1125.2 | **1145.8** |
| `dropout_p010_r8` | 0.10 | **6.9908** | **1086.6** | 1308.7 |
| `dropout_p020_r8` | 0.20 | 7.1311 | 1250.3 | 1533.8 |

`p=0.10` улучшил перплексию на обученной глубине 8 на 3,43%, но не сделал дополнительные итерации полезными: на глубинах 12 и 16 он хуже контроля на 8,41% и 14,22%. `p=0.20` ухудшил качество на всех проверенных глубинах.

Умеренное прореживание уменьшает коллинеарность обновлений около восьмой итерации, но после обученной глубины норма скрытого состояния растёт быстрее контроля. Следовательно, прореживание входа работает как регуляризатор фиксированной глубины, но не решает задачу устойчивого использования большего числа итераций. Результат получен на одном случайном зерне и является пилотным.

Полные метрики находятся в [`results/summary.csv`](results/summary.csv).

## Запуск

Из корня репозитория:

Для повторного запуска кодовая база должна содержать поддержку параметров `loop_input_dropout` и `loop_input_dropout_start` в `LoopedQwen3Config` и recurrent forward pass.

```bash
python experiments/002_loop_input_dropout/run.py --variant dropout_p010_r8
python experiments/002_loop_input_dropout/run.py --variant dropout_p020_r8
```

После получения двух JSON соберите итоговую таблицу:

```bash
python experiments/002_loop_input_dropout/summarize.py
```

Checkpoints сохраняются в `outputs/experiments/002/`, а JSON и CSV — в `experiments/002_loop_input_dropout/results/`.
